Dos cadenas de procesos para el mismo problema

Appium y CuyScout automatizan la misma app iOS sin ver su código fuente. La ventaja de coste medida en el README no sale de un truco de prompting: sale de cuántos procesos cruza cada llamada y de qué tan crudo es lo que responden.

Appium: servidor + WebDriverAgent, dos procesos CuyScout: un binario, servidor y motor en el mismo proceso ruta MCP por stdio, exclusiva de CuyScout

La diferencia que importa: qué transporta una lectura de pantalla

Las dos herramientas resuelven "qué hay en la pantalla ahora" de forma opuesta. Appium entrega el árbol de accesibilidad tal cual sale de XCTest; CuyScout lo reduce a dos listas antes de responder.

por leer el comprobante de pago una vez. El agente recibe geometría y contenedores de SwiftUI que no puede accionar, y decide él mismo qué descartar.

CuyScout · GET /session/{id}/observe 
{
  "actions": [
    { "id": "btn_service_pay",
      "role": "button", "label": "Pagar" }
  ],
  "texts": [
    "label_service_result_operation:
      N° Operación: SP860351",
    "label_service_result_amount:
      Monto pagado: S/ 120.00"
  ]
}
284 tokens

por la misma lectura. Los labels de iconos (nombres de SF Symbols) ya están filtrados; actions es para actuar, texts es para verificar.

Componente por componente

CapaAppiumCuyScout
Procesos por sesión Appium Server (Node.js) + WebDriverAgent (XCTest aparte) un binario Swift; servidor y motor en el mismo proceso
Protocolo con el agente WebDriver JSON wire protocol por HTTP HTTP compatible W3C, o MCP por stdio (tools/call)
Lectura de pantalla GET /session/{id}/source: árbol de accesibilidad completo GET /session/{id}/observe: actions + texts, ya filtrado
Verificar un dato en pantalla buscarlo dentro del árbol completo que ya se descargó ya viene en texts, con su identificador
Prueba ejecutable al terminar ninguna por defecto; el agente la escribe a mano si se le pide sesión grabada desde su creación; recording/appium/typescript exporta el flujo
Documentación como superficie de ejecución una guía externa al servidor descripciones de herramientas MCP + skill empaquetada, versionadas junto al código

Un proceso menos no es solo velocidad

Que WebDriverAgent sea un proceso XCTest separado con su propia HTTP interna no solo añade latencia: significa que la respuesta que llega al agente es la que ese proceso decide dar, sin que Appium pueda reprocesarla barato en el camino. En CuyScout, el servidor y el motor comparten memoria, así que filtrar el árbol antes de responder —lo que hace observe— no cuesta un salto de red adicional.
